# Deploy RUGD Analyze on Render

This is a pilot deployment for `app.rugdintelligence.com`. It is not a finished production service. Prototype warnings stay on. There is no rate limit, no email verification, no public self-service billing, and no customer control that sets `human_review_approved`.

The public website stays on Webflow. Do not point `rugdintelligence.com` at this service. Longarc_Platform is not part of this deployment.

## What the process runs

Render starts the app with:

```text
python -m app
```

That is the same stdlib server as the local pilot (`Procfile` and `render.yaml`). It is not gunicorn. Python 3.12 is enough. `requirements.txt` lists no third-party packages.

`RUGD_ENV=production` makes `main()` listen on `0.0.0.0` and on Render's `PORT`. Local runs leave those variables unset and stay on `127.0.0.1:8765`. A local `PORT` value does not move the local server.

The process refuses to start in production when `SECRET_KEY` is missing or shorter than 32 characters. The key is also the pepper for stored session hashes. Changing it signs existing sessions out. The raw session token is still not written to SQLite.

The database is one SQLite file. Keep the Render service at one instance. A second instance would not share that file safely.

## Create the web service

1. Push this repository to the Git host Render will read. Do not commit `.env`, `data/analyze.sqlite`, or a real `SECRET_KEY`.
2. In the Render dashboard, create a Blueprint from `render.yaml`, or create a Python web service by hand with:
   - Build command: `pip install -r requirements.txt`
   - Start command: `python -m app`
   - Health check path: `/`
   - Instance count: 1
   - Persistent disk: name `rugd-data`, mount path `/var/data`, 1 GB
3. Set the environment variables below in the Render dashboard. `render.yaml` marks secrets `sync: false` so the blueprint does not store them. `SECRET_KEY` can be generated by Render.
4. Deploy. The health check requests `/` and expects HTTP 200.

## Environment variables

The app reads `os.environ`. It does not load a `.env` file. `.env.example` is a checklist. Render injects the dashboard values.

Required:

| Variable | Value |
| --- | --- |
| `RUGD_ENV` | `production` |
| `SECRET_KEY` | at least 32 characters, generated in Render, never committed |
| `RUGD_DATABASE` | `/var/data/analyze.sqlite` |
| `RUGD_BOOTSTRAP_REVIEWER_EMAIL` | email for the first reviewer |
| `RUGD_BOOTSTRAP_REVIEWER_PASSWORD` | password for that first reviewer, at least 8 characters |

`SECURE_COOKIES=true` is set by the blueprint. `RUGD_ENV=production` already marks the session cookie Secure, HttpOnly, and SameSite=Lax. Either setting is enough for the Secure flag.

Render sets `PORT`. Do not override it.

After the first reviewer can log in, clear `RUGD_BOOTSTRAP_REVIEWER_PASSWORD` in the dashboard and redeploy. Starting again with both bootstrap variables set does not create a second reviewer and does not change an existing account. Later reviewers are created by a signed-in reviewer at `/reviewer/accounts`.

Optional, and already supported. Leave them unset to keep the Demonstration Analyst and the synthetic market snapshot:

- `ANALYST_PROVIDER`, `ANALYST_MODEL`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `XAI_API_KEY`
- `MARKET_PROVIDER`, `MARKET_CENSUS`, `MARKET_CBP`, `MARKET_BEA`, `BEA_USER_ID`, `MARKET_LAUS`, `MARKET_YEAR`, `ACS_YEAR`, `CBP_YEAR`, `BEA_YEAR`, `LAUS_YEAR`

Market extracts and the analyst still cannot clear a recommend-against flag or set `human_review_approved`.

## Custom domain and HTTPS

1. In the Render service, open Custom Domains and add `app.rugdintelligence.com`.
2. Render shows the hostname for that service, such as the `onrender.com` name on the service page.
3. At the DNS host for `rugdintelligence.com`, add a CNAME record:
   - Host: `app`
   - Target: the Render hostname shown for this service
4. Wait until Render reports the domain as verified. Render then provisions the certificate. HTTPS is automatic. Do not install a certificate in this repository.
5. Leave the apex domain `rugdintelligence.com` on the existing public website. This app is only the `app` host.

The session cookie is marked Secure in this environment, so the browser sends it on HTTPS requests to this host.

## What stays pilot-grade

- The official baseline stays do-not-proceed, `INSUFFICIENT_DEMAND_EVIDENCE`, investor readiness internal, and `human_review_approved` false.
- Prototype warnings stay on the screens. They still say the screen does not grant investor-ready status.
- There is no rate limit, account lockout, or email verification.
- Password hashing is the pilot scrypt parameter. There is no OAuth provider and no external identity provider.
- `app/future.py` stays disabled. Render settings are read from `app/config.py`. The deployment seam does not turn on billing or scoring.
- One SQLite file is the database. An external database is a later decision. `RUGD_DATABASE` is the path seam for that file.
